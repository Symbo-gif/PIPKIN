# U2 — Core decay / tick simulation

**Depends on:** U1  
**Branch:** `feature/U02-simulation-engine`  
**Modules:** `:core` `com.pipkin.core.simulation`  
**Risk:** High (feel of the game)

## Scope

Pure Kotlin. Given `PetState` + elapsed simulated minutes, return a new `PetState`.

Locked: hunger **-2 per hour** (so **-2/60 per minute**, integer math must be specified in the Session 1 plan: accumulate remainder on the state or use integer minutes with `hunger -= (2 * hours)` plus leftover minutes stored). **Decision for Session 1 plan:** use integer minutes; hunger decreases by `floor(elapsedMinutes * 2 / 60)` and store unused minute remainder on state **or** compute from timestamps only. Prefer timestamp-based: `hunger' = hunger - floor((now - lastSimulatedAt) * 2 / 3600000)` clamped to 0, applied as part of a full tick function that also applies other meters from `docs/build-plan.md` §3.1.

Also apply happiness, energy, cleanliness idle decay from the build plan. Health idle: none unless cleanliness is low (document threshold in plan; default: cleanliness < 20 drains 1 health/hour).

Energy while sleeping recovers (default +4/hour); Session 1 plan must define `isSleeping` on state if missing from U1 (spec change: add field, update U1 docs).

`lastSimulatedAtMillis` updates to the end of the simulated period.

## Out of scope

72-hour cap (U3), evolution stages (U4), Android.

## Tests (names must state behavior)

- `hunger_decays_two_points_after_one_hour`

- `meters_unchanged_for_zero_elapsed`
- `happiness_energy_cleanliness_decay_per_build_plan`
- Multi-hour integer drift tests (3h, 24h)
