# U1 — Data model & Room persistence

**Depends on:** none (U00 Closed)  
**Branch:** `feature/U01-data-model`  
**Modules:** `:app` `com.pipkin.data`, mappers to `:core` model types  
**Risk:** Medium

## Scope

- Domain types in `:core`: `PetState`, `HistoryLog` (data only; no simulation).
- Room: `PetStateEntity`, `HistoryLogEntity`, DAOs, database, type converters.
- Mappers entity ↔ domain. Save slots: 3 slot ids (`0..2`).
- Corrupt row handling: invalid meters or timestamps throw or return a typed failure; app must not crash-loop (minimal recovery hook is enough; full UI is U11).

## `PetState` fields (minimum)

`petId`, `slotId`, `name`, `hunger`, `happiness`, `energy`, `cleanliness`, `health` (all meters 0–100), `stage`, `branch`, `careMistakeCount`, `hungerZeroSinceMillis` (nullable), `lastSimulatedAtMillis`, `createdAtMillis`, `isDead`.

## `HistoryLog` fields (minimum)

`id`, `slotId`, `petId`, `eventType`, `payloadJson` or typed columns, `atMillis`.

## Out of scope

Tick engine, UI, WorkManager.

## Tests

- DAO round-trip insert/read/update for `PetState` and `HistoryLog`.
- Slot isolation: writing slot 1 does not change slot 0.
- Meter out of range on write is rejected or coerced per mapper contract (pick one in Session 1 plan; document it).
- In-memory Room in `androidTest` or Robolectric.

## Coverage

DAO and mapper unit/integration tests required. Not a 90% `:core` logic unit yet (models only).
